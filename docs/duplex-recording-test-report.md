# 双向录音测试记录

日期：2026-10-26。测试对象为当前源码，未更新 v1.2 发布包。

## 自动化验证

命令：`$env:PYTHONPATH='echoscribe'; $env:QT_QPA_PLATFORM='offscreen'; python -m pytest -q`

结果：103 passed，6.63 秒。双向录音专用测试 13 项，覆盖：

- 两路信号混合、满幅信号限幅、系统无声时麦克风信号保留。
- 44.1/48/16 kHz 采样率处理，时间戳间隙补静音。
- 正常停止、显式停止请求、麦克风权限失败、输入溢出、设备断开、麦克风没有回调数据。
- 失败路径关闭设备、释放后端、删除临时文件。
- 缓冲区有界及过载报错。
- 1 小时和 3 小时时间偏移处的数值精度；这不是连续长时间硬件录音测试，也不证明设备时钟长期无漂移。

## 本机硬件验证

输出：Realtek 扬声器 WASAPI loopback，48 kHz，双声道。
输入：英特尔数字麦克风阵列，44.1 kHz，双声道，默认输入来自 MME。

运行两次约 5 秒的测试；计时包含设备初始化，实际文件分别为 4.652 秒和 4.742 秒。输出均为 48 kHz 单声道 PCM WAV。

1. 系统未播放测试音：loopback 没有回调，麦克风收到 228 个缓冲块；录音正常结束。最终混音 RMS 为零。
2. 播放低幅 440 Hz 测试音：loopback 收到 237 个缓冲块，峰值 1541；麦克风收到 234 个缓冲块；混音 RMS 约 0.01654。

两次麦克风信号峰值均仅为 1（16 位 PCM 满幅约 32767），所以只能确认麦克风数据通路打开，不能确认真实说话声被清晰录入。需要用户说话时再做一次试听，并核对静音状态、输入设备及 Windows 输入音量。

测试录音保留在本机临时目录 `C:\Users\STZ\AppData\Local\Temp\echoscribe-duplex-check-aqqrgbbg`，未上传外部服务。

## 建议优先级

1. 独立显示麦克风和系统声音电平、设备名称，提供录前试音和持续无声提示。当前单一混音电平无法区分哪一路没有有效声音。
2. 设备断开或溢出时保留已完成的音频并标记异常。当前异常路径删除 `.part` 文件，长会议存在已录内容丢失风险。
3. 允许选择输入/输出设备，优先验证同一 WASAPI 后端，检查蓝牙耳机、USB 麦克风以及默认设备切换。
4. 增加分路增益和可选独立音轨。当前两路固定各乘 0.5，单路说话也会降低约 6 dB。
5. 进行至少一小时真实会议测试，测量双路时钟漂移、停止尾部完整性和 CPU 使用率；目前每个采样点在 Python 中处理。
6. 扬声器使用场景评估回声消除。当前建议使用耳机，混音本身不具备回声消除能力。
